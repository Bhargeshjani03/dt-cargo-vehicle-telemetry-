DT-CARGO VEHICLE TELEMETRY ANALYSIS
===================================
EDA + DATA QUALITY ANALYSIS LOG
===================================

Project:
Vehicle Telemetry Analysis for Improving Efficiency in Logistics Fleet Operations

Dataset:
DT-CARGO V2.0

Purpose of this file:
---------------------
This file records completed EDA investigations, conclusions, and the
candidate data-quality flags identified from them.

IMPORTANT:
- EDA investigations should NOT be repeated unless new evidence appears.
- Raw data must be preserved.
- Final cleaning/modeling rules will be implemented after EDA consolidation.
- A quality flag does NOT automatically mean that a record must be deleted.
- Many suspicious records may still be useful for anomaly detection.
- Raw values should be preserved for traceability.

============================================================
13. SIGNAL LOSS DEFINITIONS
============================================================

Official DT-CARGO interpretation:

n_signal_loss:
- number of signal-loss events during recording

d_signal_loss:
- distance covered during signal losses
- measured in metres
- NOT duration

r_signal_loss:
- signal-loss distance / recorded track distance

Therefore:
r_signal_loss ≈ d_signal_loss / distance

These definitions must be preserved in feature documentation.

============================================================

Conclusion:
- r_signal_loss > 1 is outside the expected ratio range.
- Preserve raw value.
- Do not delete record automatically.
- Use a validity flag and NaN processed value if required by modeling.

Candidate flags:
r_signal_loss_out_of_range
r_signal_loss_valid

============================================================
16. avg_speed > max_speed
============================================================

45,819 tracks:
avg_speed > max_speed

≈30.22% of all tracks.

This is mathematically inconsistent if both represent the same
speed quantity over the same track.

Representative raw telemetry investigations showed:
- track-level avg_speed can differ dramatically from raw speed mean
- raw telemetry mean can remain physically reasonable
- raw telemetry max generally agrees with track-level max_speed

Examples include tracks with:
- avg_speed = hundreds/thousands of m/s
- max_speed = fractions of m/s or a few m/s

Conclusion:
- Track-level avg_speed is not authoritative for affected records.
- Raw telemetry should be used when reliable high-resolution speed features
  are required.
- Preserve original avg_speed for traceability.
- Do not blindly delete all records where avg_speed > max_speed because
  this may remove useful observations from an imperfect summary field.

Candidate flag:
avg_speed_gt_max_speed

28. IMPLIED SPEED EXTREME-VALUE INVESTIGATION
============================================================

Top implied-speed records contain combinations of:
- extremely short duration
- large distance relative to duration
- avg_speed far above max_speed
- negative n_signal_loss
- high HDOP in some cases
- other previously identified telemetry-quality issues

Example:
Track 102170:
- distance = 17,535 m
- duration = 16.815 s
- avg_speed = 1042.82 m/s
- max_speed = 0.07 m/s
- implied speed ≈ 3,754 km/h
- avg_hdop ≈ 0.58
- n_signal_loss = -19,062

This cannot represent a genuine truck operating at the reported
track-level average speed.

Earlier raw telemetry investigations showed that:
- some extreme track-level avg_speed values are not supported by raw speed
  telemetry
- some genuinely high-speed tracks ARE supported by raw telemetry

Therefore:

DO NOT use:
implied_speed > X => invalid

DO NOT use:
max_speed > X => invalid

Instead:
- use implied speed as a diagnostic/derived feature
- combine it with telemetry consistency and quality information
- preserve raw observations

- 99% ≈ 1.0444

Absolute difference between avg_speed and distance/duration:
- mean ≈ 0.000136 m/s
- median ≈ 0.000355 m/s
- 95% ≈ 0.004494 m/s
- 99% ≈ 0.004910 m/s
- max ≈ 0.1081 m/s

349 tracks had ratio >1.10.

Investigation showed that many large ratios occur at extremely low
speeds where avg_speed is rounded to 0.01 m/s.

Conclusion:
- Duration is internally consistent for the overwhelming majority
  of normal moving records.
- Ratio mismatches are not automatically duration errors.
- Do not create an arbitrary duration consistency cutoff.


============================================================
32. FINAL CANDIDATE DATA-QUALITY FLAGS
============================================================

The following flags should be considered for the processed dataset.

1. insufficient_telemetry
   True when the track has missing core telemetry because the associated
   raw speed file contains only ~1-2 observations / extremely short
   telemetry span.

2. duration_invalid
   True when:
       duration_seconds < 0

3. distance_missing
   True when:
       distance is NaN

4. avg_speed_missing
   True when:
       avg_speed is NaN

5. avg_speed_negative
   True when:
       avg_speed < 0

6. avg_speed_gt_max_speed
   True when:
       avg_speed > max_speed
   Interpretation:
       track-level summary inconsistency.
   Do not automatically delete the record.

7. n_signal_loss_negative
   True when:
       n_signal_loss < 0

8. d_signal_loss_invalid
   Potentially true when:
       d_signal_loss < 0
   Current EDA found NO negative d_signal_loss values.

9. r_signal_loss_missing
   True when:
       r_signal_loss is NaN

10. r_signal_loss_out_of_range
    True when:
        r_signal_loss < 0 OR r_signal_loss > 1

11. zero_distance
    True when:
        distance == 0

12. zero_distance_speed_issue
    True when:
        distance == 0 AND max_speed > 1 m/s

13. track_gap_missing
    True when:
        track_gap is NaN

IMPORTANT:
- zero_distance is NOT automatically invalid.
- high max_speed is NOT automatically invalid.
- high implied_speed is NOT automatically invalid.
- long duration is NOT automatically invalid.
- short duration is NOT automatically invalid.
- short distance is NOT automatically invalid.

33. PROPOSED PROCESSED-VALUE RULES
============================================================

Raw columns must remain unchanged.

For modeling/analysis copies:

avg_speed:
- negative values -> NaN
- potentially unreliable where avg_speed > max_speed
- raw telemetry-derived speed features preferred when available

n_signal_loss:
- negative values -> NaN

r_signal_loss:
- values outside [0,1] -> NaN
- missing values remain missing

duration:
- negative duration -> NaN for duration-dependent modeling
- timestamps themselves remain preserved

distance:
- missing remains NaN
- zero distance remains zero

track_gap:
- missing remains NaN
- do not impute with zero

No blanket row deletion should be performed based solely on any one flag.

============================================================
35. IMPORTANT FEATURE-ENGINEERING PRINCIPLES FROM EDA
============================================================

1. Distance is highly right-skewed.
   Consider log transformation or robust scaling.

2. Duration is highly right-skewed.
   Consider log transformation or robust scaling.

3. Distance and duration are strongly related.
   Avoid excessive redundant features.

4. avg_speed is not always trustworthy as a summary field.
   Raw speed telemetry should be used to derive robust speed features
   where possible.

5. max_speed appears much more consistent with raw telemetry in inspected
   samples, but extreme values should still be interpreted contextually.

6. Context variables are not interchangeable:
   - long_haul
   - home_base
   - industrial_area
   - rest_area
   - service_area_fuel

7. axle_class is categorical/configuration-like.

8. Vehicle specifications have structured missingness.

9. Dataset is episodic rather than continuously monitored.

10. Vehicle-level observation counts are highly imbalanced.

11. tour_id is not vehicle-specific.

12. Raw speed data should be processed separately rather than loading all
    high-resolution telemetry into memory at once.

the value is invalid or unusable for a particular model.

may later become:
